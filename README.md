# bluishCanvas

무한 캔버스 위에 도형과 텍스트를 배치하고 화살표로 연결하는 개인용 시각적 메모 도구.
여러 개의 캔버스("페이지")를 만들고 폴더로 정리할 수 있다.

**배포 주소 (GitHub Pages):** https://bluishgrey.github.io/bluishCanvas/

## 실행 방법

빌드 과정이 없다. `index.html` 파일을 웹 브라우저로 열면 된다.
(파일 탐색기에서 더블클릭하거나, 브라우저 창에 드래그 앤 드롭)

또는 위 배포 주소로 바로 접속해서 브라우저에서 열 수도 있다. 다만 이 경우 데이터는
그 브라우저의 `localStorage` 에 저장되므로, 로컬로 열었을 때와 페이지를 열 때마다
사용한 방식(파일 직접 열기 vs 배포 주소)에 따라 서로 다른 저장 공간을 쓴다는 점에
주의한다(둘 사이 데이터 이동은 내보내기/가져오기 사용).

## 현재 구현된 기능 (1단계 + 조작 개선 + 다중 선택 + 실행취소 + 크기 조절 + 도형 + 화살표 + 페이지/폴더 + 백업 + 꾸미기 + 검색 + UI 개선 + Mermaid 내보내기/가져오기 + 자동 재배치)

| 동작 | 방법 |
|---|---|
| 다이어그램 타입 지정 | 우측 상단 토글 또는 **Tab** 으로 "다음에 만들 도형"의 타입(플로우차트/마인드맵)을 정한다. 이미 만든 도형은 **꾸미기** 패널 또는 그 도형을 **Shift+우클릭**해서 뜨는 빠른 메뉴에서 변경(그룹에 속해 있으면 그룹 전체가 함께 바뀐다. 다중 선택 상태에서도 동작). Shift 없는 보통 우클릭은 그대로 화살표 연결을 시작한다. 타입은 페이지가 아니라 **도형 단위**라서 한 페이지에 두 종류가 섞여 있어도 된다. 도형 자체의 생김새는 타입과 무관하게 항상 같다 — 타입 구분은 그룹 이름표의 모양(플로우차트=각진 배지, 마인드맵=캡슐 배지)과 타입 아이콘(**🔀** 플로우차트 / **🧠** 마인드맵)이 맡는다 |
| 도형-그룹 소속 확인 | 도형에 마우스를 올리면 "그룹: OO" 툴팁이 뜬다(브라우저 기본 툴팁). 어느 그룹에도 안 속한 도형은 툴팁이 뜨지 않는다. 그룹에 속하지 않은 도형은 테두리가 **점선 + 주황색**으로 표시돼 한눈에 구분된다(단계/시작·끝은 진짜 border 속성이라 점선 그대로, 분기/준비·설정/입력/출력은 배경색으로 테두리를 흉내내는 방식이라 점선은 못 쓰고 대신 배경 전체가 주황색이 된다). 왼쪽 위 모서리에는 그 도형의 용도(단계/분기/시작·끝/준비·설정/입력/출력)를 알려주는 작은 주황 글자 라벨도 함께 뜬다 — 그룹 소속 도형은 그룹 이름표의 타입 배지로 이미 알 수 있어 이 라벨이 굳이 필요 없으므로 안 뜬다. 그룹에 속한 도형은 지금처럼 실선 테두리 그대로다 |
| 올가미로 그룹 묶기 | **L** 또는 툴바 **◌ 올가미** → 도형들을 자유곡선으로 감싸면 그룹이 된다(**Esc** 로 모드 해제, 그룹이 실제로 하나 만들어지면 자동으로 일반 선택 모드로 돌아간다). 그룹은 옅은 박스로 표시되며, 배경색은 타입과 무관하게 항상 같다(순전히 "여기가 그룹 영역이다"만 나타낸다 — 타입 구분은 도형 모서리 둥글기가 대신 맡는다, 아래 "메모 꾸미기" 항목 참고). 감싼 도형이 **전부 미배정**(어느 그룹에도 안 속함)이면 새 그룹을 만든다(타입이 섞여 있으면 타입별로 나뉘고, 타입 미지정 도형은 같이 묶인 쪽에 흡수). **이미 있는 그룹의 도형 + 미배정 도형**이 섞여 있으면 새 그룹을 만들지 않고 미배정 도형만 그 그룹에 편입한다. **서로 다른 그룹 여러 개**가 걸리면 멤버가 더 많은 그룹으로 나머지가 전부 합쳐지고(작은 쪽은 사라짐), 흡수된 도형은 승자 그룹의 타입을 따라간다. 도형 하나는 한 그룹에만 속한다(중첩 없음) |
| 그룹 이름 변경 / 해제 | 그룹 박스의 이름 **더블클릭**(이 이름이 Mermaid 의 subgraph 이름이 된다), 이름 옆 **×** 로 그룹만 해제(도형은 그대로) |
| 그룹 우클릭 메뉴 | 그룹 박스나 이름표를 **우클릭**하면 메뉴가 뜬다 — **그룹 전체 선택**, **이름 변경**, **타입 전환**(플로우차트↔마인드맵 토글. 마인드맵으로 바꿀 때 그룹 안 화살표가 트리가 아니면 거부하고 이유를 알려준다), **그룹 복제**(도형+화살표+상대 위치를 그대로 복사해 원본 옆에 새 그룹으로 놓는다), **잠그기/잠금 해제**, **그룹 해제** |
| 그룹에 도형 추가 (드래그) | 도형을 **드래그**해서 그룹 **이름표 위**에 놓으면 그 그룹에 편입된다. 드래그하는 동안 이름표 위를 지나가면 이름표가 흰 점선으로 커지고, 커서 옆에도 **"OO 그룹에 추가"** 배지가 떠서 놓을 자리를 바로 알 수 있다(시선이 옮기는 도형에 가 있어도 놓치지 않도록). 박스 배경(이름표가 아닌 곳)에 놓는 건 편입으로 치지 않는다. 이미 다른 그룹 소속이던 도형이면 그 그룹에서 빠져나와 새 그룹으로 옮겨가고, 이미 명시적으로 다른 타입이 지정된 자유 도형은(그 선택을 몰래 바꾸지 않으려고) 편입되지 않는다 |
| 그룹 안에 바로 메모 만들기 | 그룹 박스의 배경(이름표가 아닌 빈 곳)을 **우클릭**하면 퀵메뉴 위에 "OO 그룹에 추가됨" 안내가 뜨고, 거기서 만든 메모가 바로 그 그룹의 멤버 + 그 그룹의 타입으로 생성된다 |
| 그룹 잠금 | 잠근 그룹은 이름표 옆에 **🔒** 가 표시된다. 잠긴 그룹은 올가미로 도형을 추가/제거할 수 없고(그 그룹은 올가미 동작에서 아예 빠진다), 드래그나 우클릭 메뉴로도 새 도형을 넣을 수 없으며, 그 도형은 드래그로 옮길 수도, 그룹에서 뺄 수도 없다(다른 선택된 도형과 함께 끌어도 잠긴 것만 제자리에 남는다) |
| 그룹에서 도형 빼기 | 그룹 소속 도형에 마우스를 올리면 삭제(**×**) 버튼 옆에 **−** 버튼이 나타난다 — 클릭하면 그 도형만 그룹 멤버에서 빠지고(도형 자체는 삭제되지 않음), 그룹 박스는 남은 멤버들에 맞춰 다시 계산된다. 같은 동작을 도형(들)을 선택했을 때 사이드바 **꾸미기** 패널의 "− 그룹에서 빼기" 버튼으로, 또는 **2개 이상 선택**했을 때 선택 경계 상자 우측 상단에 나타나는 같은 모양(원형 **−**)의 버튼으로도 할 수 있다(셋 다 다중 선택 시 그 중 그룹에 속한 것만 전부 빠진다). 그룹은 위치 기반으로 자동 재계산되는 박스라 드래그로 "밖으로" 빼낼 수 없어서, 이 버튼들이 유일한 제거 경로다. 잠긴 그룹의 도형은 전부 비활성화/숨김 처리된다. 어느 방법으로 빼든 그룹에 도형이 하나도 안 남으면 그룹 자체가 자동으로 사라진다 |
| 다중 선택 한번에 삭제 | **2개 이상 선택**하면 경계 상자 우측 상단, "그룹에서 빼기(−)" 버튼 바로 오른쪽에 개별 메모 삭제 버튼과 똑같이 생긴 **×** 버튼이 뜬다(그룹 소속 여부와 무관하게 항상 뜸). 클릭하면 선택된 도형 전부와 그에 딸린 화살표가 한 번에 삭제된다 — **Delete/Backspace** 키와 동일한 동작을 마우스로 |
| Mermaid 내보내기 | 툴바 **⤴ Mermaid** → 현재 페이지를 Mermaid 텍스트로 변환해 보여준다. 블록마다 **복사** 버튼이 있어 클로드에게 바로 붙여넣을 수 있다. Mermaid 는 문서 하나에 다이어그램 타입을 하나만 담을 수 있어서, 한 페이지에 두 타입이 섞여 있으면 **플로우차트 블록 1개 + 마인드맵 그룹마다 블록 1개**로 나뉘어 나온다. 변환에서 빠진 것(타입 미지정 도형, 타입이 다른 도형을 잇는 화살표 등)은 위쪽에 경고로 알려준다 |
| Mermaid 가져오기 | 툴바 **⤵ Mermaid 가져오기** → 팝업에 flowchart/mindmap 텍스트를 붙여넣고 **가져오기**. 좌표가 없는 텍스트라 자동 배치하는데, flowchart 는 [dagre](https://github.com/dagrejs/dagre)(계층형), mindmap 은 [d3-hierarchy](https://github.com/d3/d3-hierarchy) 의 방사형(radial) 트리 레이아웃을 쓴다(실제 Mermaid 공식 렌더러가 마인드맵엔 계층형이 아니라 방사형 엔진을 쓰는 것과 맞춰서) — 루트가 중심에 오고 자식들이 그 둘레에 균등한 각도로, 손자는 더 바깥 원에 놓인다. 결과는 현재 화면 중심 근처에 나타난다(어디 있는지 몰라 화면 밖 멀리 그려지는 일이 없도록). 한 번에 여러 블록(flowchart/mindmap 섞어도 됨)을 붙여넣으면 서로 겹치지 않게 나란히 배치한다. flowchart 의 `subgraph`는 그룹이 되고(이름도 그대로 반영), mindmap 은 들여쓰기 계층을 부모→자식 화살표로 바꾼 뒤 그룹 하나로 만든다(그룹 이름은 루트 도형의 텍스트). 도형 문법(아래 "Mermaid 변환 규칙" 표)은 6종 도형으로 정확히 매핑되고, 새로 만들어진 도형은 다른 도형과 완전히 동일하게 이동·크기조절·타입변경·삭제할 수 있다. 알아볼 수 없는 줄은 건너뛰고 나머지는 최대한 가져오며, 무엇을 건너뛰었는지·구조 자체를 못 찾았는지는 팝업 안에 노란 경고로 알려준다. 가져오기 전체가 실행취소(Ctrl+Z) 한 단계로 묶인다 |
| 사이드바 페이지/폴더 검색 | 사이드바 상단 검색창에 입력하면 이름이 일치하는 페이지/폴더만 트리에 남고 나머지는 숨겨진다. 일치하는 페이지가 들어있는 폴더는 자동으로 펼쳐져서 보인다. 검색창을 비우면 원래 전체 트리(펼침/접힘 상태 포함)로 돌아온다 |
| 캔버스 메모 검색 | **Ctrl+F** 또는 우측 상단 **🔍** 버튼을 누르면 화면 위쪽에 검색창이 뜬다(브라우저 기본 찾기 대신). 입력하면 현재 페이지 안에서 텍스트가 일치하는 메모들이 노란 테두리로 하이라이트되고 첫 번째 결과로 화면이 자동으로 이동한다. **Enter**(다음)/**Shift+Enter**(이전)로 결과 사이를 순환 이동, **Esc**로 검색창을 닫는다 |
| 조작법 안내 | 화면 우측 하단 **?** 버튼을 누르면 그 바로 위에 조작법 안내 팝업이 뜬다(화면을 어둡게 덮지 않음). 내용은 화면조작/생성편집/선택이동/화살표/히스토리/꾸미기/사이드바/검색 항목별로 나뉘어 있다. 팝업 바깥을 클릭하거나 **Esc** 로 닫힌다 |
| 메모 꾸미기 | 메모(들)를 선택하면 사이드바 하단 **꾸미기** 패널에 다이어그램 타입(플로우차트/마인드맵/미지정)과 "그룹에서 빼기" 버튼이 나타난다. 여러 메모가 선택돼 있으면 타입 변경은 전부 동일하게 적용된다. 선택이 없으면 "메모를 선택하세요" 안내만 보인다. 변경은 실행취소(Ctrl+Z) 대상이고, 저장/내보내기·가져오기에도 함께 포함된다. (배경색·텍스트 크기·정렬·테두리 굵기는 Mermaid 변환에 전혀 반영되지 않아 패널에서 뺐다 — 이전에 꾸며둔 메모의 값 자체는 데이터에 남아있어 그대로 보인다) |
| 재배치 | 툴바 **⇄ 재배치** 버튼 — 확인 후, 선택된 도형이 있으면 **딱 그 선택된 도형들만**, 없으면 페이지 전체를 Mermaid 배치 규칙대로 다시 정렬한다(선택된 도형이 그룹에 속해 있어도 그룹 전체로 확장되지 않는다 — 큰 그룹의 일부만 정리하고 싶을 때를 위해서). 정렬 알고리즘은 대상 그룹의 타입에 따라 자동으로 갈린다 — **플로우차트는 dagre(계층형)**, **마인드맵은 d3-hierarchy(방사형)**, 위 "Mermaid 가져오기"와 완전히 동일한 기준. 동작 원리는 그 범위를 Mermaid 텍스트로 바꿨다가(기존 내보내기 로직 재사용) 곧바로 다시 파싱해서 좌표만 다시 계산하는 것(기존 가져오기 로직 재사용) — 도형을 지우고 새로 만들지는 않아서 배경색·자동크기 상태 등은 그대로 유지된다. 원래 있던 자리 언저리를 중심으로 정리되고, 실행 전 "선택된 N개 도형을 자동 배치하시겠습니까?"(선택 없으면 "캔버스 전체 N개") 확인을 거친다. **마인드맵 그룹을 재배치하면 마인드맵에 대응 모양이 없는 도형(입력/출력)은 실제 도형도 사각형(단계)으로 바뀐다**(다시 파싱된 도형을 그대로 반영 — 내보내기 경고에서만 알려주고 화면은 그대로 남지 않는다). Mermaid 로 표현 안 되는 정보(도형 크기, 잠긴 그룹의 잠금 상태 등)는 일반 내보내기/가져오기와 마찬가지로 사라지고, 타입 미지정 도형처럼 애초에 변환에서 빠지는 도형은 원래 자리·모양 그대로 남는다(경고로 알려줌) |
| 전체 내보내기 | 사이드바 하단 **⬇ 내보내기** 버튼 — 모든 페이지/폴더/메모/화살표를 JSON 파일 하나로 다운로드. 파일명에 날짜·시간이 들어간다(`bluishCanvas-backup-2026-09-12_161653.json`). 완료되면 파일명이 담긴 확인 메시지가 뜬다 |

| 폴더 펼치기/접기 | 폴더 행 클릭(이름 포함) 또는 세모(▸/▾) 클릭 |
| 이름 변경 | 페이지/폴더 이름 **더블클릭**, 또는 행에 마우스를 올리면 나오는 **✎** 버튼 → 입력 → Enter(저장)/Esc(취소) |
| 페이지/폴더 삭제 | 행에 마우스를 올리면 나오는 **×** 버튼. 폴더 삭제 시 안의 페이지도 모두 함께 삭제되며, 페이지가 하나라도 있으면 확인창이 뜬다. 마지막 남은 페이지는 삭제할 수 없다 |
| 사이드바 다중 선택 | **Ctrl+클릭**으로 항목을 선택에 추가/제거, **Shift+클릭**으로 마지막 선택 지점부터 범위 선택 |

| 메모 생성 | 빈 곳 더블클릭 — 현재 "다음 생성 도형"으로 생성됨 |
| 텍스트에 맞춘 자동 크기 조정 | 도형 높이는(너비는 그대로) 항상 지금 텍스트 양에 정확히 비례해서 자동으로 계산된다 — 텍스트가 늘면 커지고, 줄면 다시 기본 크기(70)까지 작아진다. Mermaid 가져오기로 막 생성된 도형도 처음부터 이 기준으로 크기가 정해진다. 도형 모서리를 **드래그해서 수동으로 리사이즈**한 순간부터는 그 도형만 자동 크기 조정 대상에서 완전히 빠지고, 이후로는 텍스트가 어떻게 바뀌든 그 수동 크기가 계속 유지된다 |
| 다음 생성 도형 전환 | 숫자 **1**(단계) / **2**(분기) / **3**(시작/끝) / **4**(준비/설정) / **5**(입력) / **6**(출력), 우측 상단 미니 팔레트의 도형 아이콘 클릭, 또는 빈 곳 **우클릭** 퀵메뉴에서 선택 — 셋 다 완전히 동일하게 동작하고 항상 서로 맞춰 표시된다. 팔레트 아이콘 모서리에 단축키 숫자가 작게 표시되고, 현재 도형은 강조색으로 표시됨. 이름은 기하학적 모양이 아니라 흐름도에서의 용도(Mermaid 표준 도형 이름)를 그대로 쓴다 |

| 화살표 연결 | 메모를 **우클릭**하면 연결 모드로 들어가 커서를 따라 점선이 나타남. 다른 메모를 클릭하면 그 메모로 연결 완성(화살촉은 도착 쪽), **빈 곳 클릭**이나 **Esc**로 취소. 연결 지점은 상/하/좌/우 4개 고정 위치가 아니라, 두 메모의 중심을 잇는 직선이 각 도형의 **실제 윤곽**(마름모의 대각선 변, 육각형·평행사변형의 빗변, 시작/끝의 둥근 끝 등)과 만나는 정확한 지점 — Mermaid 가 실제로 그리는 방식과 비슷하게, 각도에 따라 그 변의 어느 지점이든 자연스럽게 연결점이 된다. 메모를 옮기거나 크기를 바꾸면 매번 다시 계산된다 |

| 화살표 삭제 | 선택 후 **Delete/Backspace**, 또는 선택 시 나타나는 **×** 버튼 클릭(메모의 호버형 삭제 버튼과 같은 생김새, 트리거만 호버 대신 선택). 연결된 메모를 삭제하면 그 화살표도 자동으로 함께 삭제됨 |

| 메모 선택 (다중) | 빈 곳을 (좌)드래그해 사각형 영역으로 여러 메모를 한 번에 선택 |

| 메모 편집 | 메모 더블클릭 후 입력 (한 번에 하나씩만 가능) |
| 메모 이동 | 선택된 메모(들)를 드래그 — 여러 개가 선택되어 있으면 다같이 이동 |
| 메모 크기 조절 | 선택하면 모서리에 나타나는 핸들을 드래그. 기본은 가로/세로 자유 조절, **Shift**+드래그면 원래 비율 유지. 여러 개가 선택되어 있으면 선택 영역 전체를 하나의 사진처럼 확대/축소하듯 위치와 크기, 메모 사이 간격까지 함께 비례해서 바뀜 |

빈 곳 우클릭은 퀵메뉴를 열고, 메모 위 우클릭은 화살표 연결 모드를 시작한다. 화살표는 단방향(시작 → 끝)만 지원하며,
메모 하나를 다른 여러 메모와 연결하는 것도 가능하다. 이미 만든 화살표의 시작/끝 메모를 나중에 바꾸는 기능은 없다
(화살표를 지우고 다시 연결해야 한다).

특성상 텍스트 영역을 도형보다 안쪽으로 줄여서(도형마다 다른 비율의 여백) 어떤 경우에도 글자가 도형
밖으로 삐져나가지 않게 했다. 메모를 선택하면 실제 경계 상자를 점선으로 같이 보여주는데, 사각형이 아닌
도형은 모양이 경계 상자 모서리까지 채우지 않아서 크기조절 핸들과 삭제 버튼이 도형 바깥의 "빈 공간"에
있는 것처럼 보일 수 있기 때문이다 — 점선을 보면 핸들/삭제 버튼이 실제로는 정확한 위치(경계 상자 모서리)에
있다는 걸 확인할 수 있다.

여러 메모에 한 번에 서로 다른 텍스트를 입력하는 기능은 없다. 텍스트 편집은 항상 메모 하나씩 더블클릭해서 한다.

실행취소/다시실행은 메모의 생성·이동·삭제·텍스트 수정·꾸미기(배경색/글자크기/정렬/테두리굵기),
화살표의 생성·삭제·라벨 수정을 기록한다(화면 이동·확대축소는 기록되지 않음). 텍스트/라벨 수정은
글자 하나하나가 아니라 편집을 마치고 밖을 클릭했을 때 한 단계로 기록된다. 기록은 최근 50단계까지만
유지되며, 브라우저를 새로고침하면 초기화된다(저장되는 내용 자체는 유지됨).

각 페이지는 독립적인 무한 캔버스다 — 팬/줌/메모/화살표/선택/실행취소 기록이 페이지마다 따로 관리된다.
페이지를 전환해도 다른 페이지의 실행취소 기록은 그 세션 동안(새로고침 전까지) 유지된다.

전체 구조(폴더 트리 + 모든 페이지의 내용)는 브라우저 `localStorage` 에 자동 저장되어 새로고침해도 유지된다.
(저장 위치는 브라우저별로 분리됨. 다른 브라우저/기기와는 공유되지 않음 — 기기를 옮길 땐 내보내기/가져오기 사용)

이 기능이 생기기 전에 저장돼 있던 캔버스 내용은 처음 열 때 자동으로 "기본 페이지"라는 이름의 페이지로 옮겨온다.

## 기술 스택

- 순수 HTML / CSS / JavaScript, 빌드 도구·서버 없음. 외부 의존성은 Mermaid 가져오기/재배치의 자동 배치에 쓰는
  레이아웃 라이브러리 둘뿐이고, 그것도 npm 설치 없이 `index.html` 에서 CDN `<script>` 태그로 불러온다 —
  flowchart 는 [dagre](https://github.com/dagrejs/dagre)(계층형), mindmap 은 [d3-hierarchy](https://github.com/d3/d3-hierarchy)
  (방사형/radial 트리) — 실제 Mermaid 공식 렌더러가 마인드맵엔 dagre 가 아니라 별도의 방사형 엔진을 쓰는 것과
  맞춰서 좌표 없는 텍스트에서 좌표를 만들어내는 계산을 직접 구현하지 않고 각 다이어그램 타입에 맞는 검증된
  라이브러리를 그대로 쓴다(`layoutBlock()` 이 블록 타입에 따라 갈라 부른다)
- 무한 캔버스는 `#world` 컨테이너에 CSS `transform: translate() scale()` 을 적용해 구현
- 상태: `view = { x, y, scale }` + `notes = [{ id, x, y, w, h, text, shape, bg, fontSize, textAlign, borderWidth, diagramType, autoSize }]`(`shape`: `rect` | `ellipse` | `diamond`; `bg`: 커스텀 배경색 hex 또는 `null`=기본값; `diagramType`: `flowchart` | `mindmap` | `null`=미지정; `autoSize`: `false`가 아니면(기본값) 텍스트 양에 맞춰 높이가 자동으로 계산되고, 수동 리사이즈 이후엔 `false`로 고정된다) + `arrows = [{ id, fromId, toId, label? }]` + `groups = [{ id, name, noteIds, locked }]` — 이 전체가 페이지 하나의 내용이다
- 페이지 하나의 상태를 만들고 되돌리는 건 `makeSnapshot()` / `applySnapshot()` 한 쌍이 전담한다. 실행취소 스냅샷과
  페이지 저장이 같은 모양을 쓰기 때문에, 상태 필드가 늘어날 때 이 두 함수만 고치면 된다(예전엔 같은 모양이 여섯 군데에
  중복돼 있어서 한 곳만 빠뜨려도 "실행취소하면 새 필드가 사라지는" 버그가 나기 쉬웠다)
- 그룹은 다이어그램 타입을 따로 저장하지 않고 **멤버 도형의 `diagramType` 에서 파생**한다. 두 군데 저장하면 어긋날 수
  있어서 진실을 한 곳에만 둔 것이고, 대신 그룹에 속한 도형의 타입을 바꾸면 그룹 전체가 같이 바뀐다(그룹은 항상 단일 타입)
- 그룹 박스는 `#world` 의 맨 앞 자식인 `#groups-layer` 에 그린다 — 월드 좌표계라 팬/줌을 저절로 따라가고(화살표 레이어와
  같은 원리), 맨 앞 자식이라 화살표/메모보다 뒤에 깔린다. 드래그 중에는 박스를 다시 만들지 않고 위치·크기만 갱신한다
- 올가미로 도형을 감쌀 때, 이미 있는 그룹의 멤버가 섞여 있으면 새 그룹을 만드는 대신 기존 그룹에 합친다(여러 그룹이
  걸리면 멤버가 가장 많은 쪽이 이긴다). 잠긴 그룹은 이 판단에서 아예 제외되어 멤버가 추가/제거되지 않는다. 그룹
  우클릭 메뉴의 "마인드맵으로 전환"은 Mermaid 내보내기가 쓰는 것과 같은 트리 판정 함수(`buildMindmapTree`)를 재사용해서,
  화살표가 트리가 아니면 전환 자체를 막는다
- 도형을 그룹 이름표에 드래그해 놓는 판정은 `document.elementFromPoint()`로 한다. 드래그 중인 도형 자신이 커서
  바로 밑을 가리고 있으면 그 아래 이름표를 못 찾으므로, 판정 순간에만 드래그 중인 도형의 `pointer-events`를 잠깐
  꺼서 "그 밑에 뭐가 있는지" 확인한 뒤 되돌린다
- `#world`/`#groups-layer` 는 모두 `width:0; height:0`(내용은 전부 절대위치 자식이 채움)이라 그 자체는 클릭을
  받지 않는다. 그래서 그룹 박스 배경(`pointer-events:none`) 안에서 우클릭해도 `e.target`은 그 뒤에 있는
  `#canvas` 그대로다 — 이 덕분에 "그룹 영역 안 우클릭"을 캔버스의 기존 퀵메뉴 로직에 자연스럽게 끼워 넣을 수 있었다
  (좌표가 어느 그룹의 경계 상자 안인지만 추가로 검사하면 됨, `e.target` 판정 자체는 그대로)
- 그룹 박스는 소속 도형들의 위치로부터 매번 다시 계산되는(`groupBounds`) 값이라, 드래그로 "그룹 밖으로" 빼내려 해도
  박스가 같이 넓어지며 따라와서 빠질 수 없다. 그래서 그룹에서 도형을 빼는 건 드래그가 아니라 명시적인 버튼(메모
  자체의 −버튼 / 꾸미기 패널)으로만 한다. 각 메모의 −버튼이 지금 보이는지/눌리는지는 `renderGroups()` 끝에서
  `updateNoteGroupButtons()`를 호출해 한 곳에서 관리한다 — 그룹 구조가 바뀌는 경로(올가미/드래그편입/우클릭생성/
  해제/잠금/복제/빼기)가 전부 이미 `renderGroups()`를 부르고 있어서, 새 진입점마다 버튼 상태를 따로 챙기지 않아도 된다
- 메모 꾸미기(배경색/테두리굵기)는 6종 도형 모두 CSS 변수(`--note-custom-bg`, `--note-border-width`)로 처리한다.
  clip-path 도형(분기/준비·설정/입력/출력)은 `clip-path` 로 잘린 `::after` 가상요소가 실제 배경/테두리를
  담당하는데, 가상요소는 JS에서 직접 인라인 스타일을 줄 수 없어서 `.note` 엘리먼트에 CSS 변수를 얹어두고 각
  도형별 CSS 규칙이 그 변수를 참조하게 만들었다 — 이렇게 하면 도형이 뭔지 JS 쪽에서 따로 분기하지 않아도 된다.
  텍스트 크기/정렬은 `.note-text` 에 직접 인라인 스타일로 준다
- **도형 종류와 다이어그램 타입은 완전히 독립된 두 축이다.** 예전엔 마인드맵 타입일 때 도형 모서리도 같이
  둥글어지는 로직이 있었는데(플로우차트=각진 모서리, 마인드맵=캡슐/둥근 모양), 그룹 이름표에 타입 아이콘
  (🔀/🧠)이 이미 붙어 있어서 중복이라 판단해 전부 제거했다 — 지금은 `.note[data-shape="…"]` 만으로 도형이
  정해지고, `data-diagram-type` 은 그룹 이름표/그룹 박스 스타일에만 쓰인다(도형 자체 CSS는 안 읽는다)
- clip-path 로 모양을 오려내는 도형 4종(분기/준비·설정/입력/출력)은 렌더링 방식이 전부 똑같아서(이중 레이어로
  테두리 흉내·drop-shadow·선택 링·그룹 미소속 경고색) 공통 CSS 블록 하나를 공유한다 — 각 도형은 `--note-clip`
  이라는 CSS 커스텀 속성에 자기 폴리곤(`--diamond-clip`/`--hexagon-clip`/`--parallelogram-clip`/
  `--parallelogram-rev-clip`)만 지정하고, 나머지 규칙은 전부 `var(--note-clip)` 을 참조한다. `border-radius` 가
  clip-path 에는 안 먹혀서(뾰족한 다각형이라 `clip-path: path()` 로 진짜 곡선을 그리려면 % 가 아닌 절대 좌표가
  필요하고, 크기가 자유롭게 바뀌는 메모에는 못 쓴다) 이 방식으로 통일했다 — 앞으로 clip-path 도형이 더
  생겨도 폴리곤 변수 하나 + 공통 블록의 선택자 목록 한 줄만 추가하면 된다. 시작/끝(스타디움)은 진짜
  `border-radius` 로 처리한다(값을 박스 높이보다 훨씬 크게 주면 자동으로 반원 두 개로 clamp 된다) — clip-path
  가 필요 없는 유일한 비사각형 도형이라 이중 레이어 흉내도 필요 없다
- 여러 페이지: `tree`(폴더/페이지 트리) + `pagesData`(페이지 id → 위 상태 전체)로 관리한다. "페이지 전환"은 지금
  화면에 그려진 내용을 통째로 다른 페이지 것으로 바꿔치기하는 것과 같다(실행취소의 스냅샷 복원과 같은 원리)
- clip-path 도형은 배경 레이어(`.note-shape`)에만 `clip-path` 를 걸어 잘라내고, 텍스트/삭제버튼은 별도 레이어라 잘리지 않게 분리했다
- 화살표는 `#world` 안의 SVG 레이어(`#arrows-layer`)에 그린다. 메모와 같은 부모의 transform 을 그대로 받기 때문에
  팬/줌 때 따로 계산할 필요가 없고, 좌표는 항상 월드 단위로만 다룬다. 연결 지점은 저장하지 않고
  메모가 움직이거나 크기가 바뀔 때마다 두 메모의 위치를 보고 매번 새로 계산한다
- 화살표 연결 지점은 경계 상자의 상/하/좌/우 4개 고정 지점이 아니라, 두 도형의 중심을 잇는 직선이 각
  도형의 실제 윤곽과 만나는 지점을 계산해서 정한다(`shapeExitPoint`) — Mermaid 가 실제로 그리는 방식에
  가깝게. 도형은 두 갈래로 계산한다: 단계(사각형)·분기(마름모)·준비/설정(육각형)·입력/출력(평행사변형
  2종)은 전부 도형 윤곽을 이루는 정점(0~1 비율, clip-path 폴리곤과 정확히 같은 좌표)만 다르고 알고리즘은
  하나다 — 도형 중심에서 상대 도형 방향으로 쏜 반직선이 그 다각형의 어느 변과 만나는지(교차하는 변이
  볼록 다각형에선 정확히 하나) 표준 선분 교차 공식(외적 기반)으로 구한다. 시작/끝(스타디움)만 `border-
  radius:999px` 로 반지름이 `min(너비,높이)/2` 로 clamp 된 반원 두 개 + 직선 두 개짜리 합성 도형이라
  따로 계산한다(반직선-원 교차의 2차방정식 + 반직선-직선분 교차를 함께 써서, 어느 쪽 경계를 만나는지
  가로/세로 어느 쪽이 더 긴 도형이냐로 방향을 미리 정하고 판정한다 — 자동 높이 조정으로 세로가 더
  길어지는 경우까지 가정한다). 화살표 드래프트(연결 중 커서를 따라가는 점선 미리보기)도 커서를 목표
  지점으로 같은 함수를 그대로 쓴다
- 화살표 라벨 편집칸은 SVG `<foreignObject>` 안에 진짜 `<input>`을 띄우는 방식이다. arrows-layer 가
  #world 의 자식이라 팬/줌 transform 을 그대로 물려받으므로, 입력칸이 화면 좌표를 따로 계산하지 않아도
  화살표를 따라 움직이고 확대/축소도 자동으로 맞춰진다
- 화살표 삭제(×) 버튼은 선의 정확히 중간(50%)이 아니라 25% 지점에 둔다. 라벨은 항상 정중앙에,
  화살표 각도와 무관하게 회전하지 않은 채 가로로 넓게 펼쳐지는 모양으로 놓이기 때문에, "중간에서
  수직으로 살짝 띄우기" 방식으로는 화살표가 세로에 가까울 때 라벨과 겹치는 걸 못 피한다 — 아예
  다른 지점에 두면 각도·라벨 길이와 상관없이 항상 안 겹친다
- 텍스트에 맞춘 자동 크기 조정(`measureNoteFitHeight`)은 화면에 안 붙는 오프스크린 프로브를 실제
  `.note`/`.note-text` 와 완전히 같은 클래스로 만들어 측정한다 — 도형별 텍스트 인셋 비율(분기 25%, 준비/설정
  15%/28% 등)을 여기 따로 하드코딩하지 않고, 실측한 `scrollHeight`/`clientHeight` 비율을 그대로 역산에
  쓰기 때문에 나중에 CSS 인셋이 바뀌어도 이 계산이 저절로 따라간다. 구현하면서 잡은 진짜 까다로운
  버그 하나: `.note-text` 는 `align-items:center` 로 세로 가운데 정렬을 하는데, 내용이 넘치면 이 정렬이
  넘친 부분을 위/아래로 절반씩 밀어내고 `scrollTop` 은 음수로 못 가서 `scrollHeight` 가 위로 넘친
  절반을 못 세고 실제보다 작게(대략 `(박스높이+실제내용높이)/2`) 보고한다 — 게다가 박스를 그 값만큼
  키워도 또 그만큼 부족한 것처럼 보이는 식으로, 박스 높이가 바뀔 때마다 측정값 자체가 달라져서 한
  번에 정확한 필요 높이를 구할 수가 없었다(88로 키웠는데도 여전히 넘치는 식). 측정용 프로브에서만
  `align-items:flex-start` 로 바꿔서 넘친 내용이 전부 아래로만 쌓이게 하면, `scrollHeight` 가 박스
  높이와 무관한 진짜 내용 높이를 정확히 돌려준다(실제로 보이는 도형은 원래대로 가운데 정렬 그대로 —
  바뀌는 건 이 임시 프로브 하나뿐이다). 세로 가운데 정렬된 오버플로우 콘텐츠의 scrollHeight 를 재는
  코드는 앞으로도 이 함정을 다시 만날 수 있으니 기억해 둘 만하다
- 자동 크기 조정은 처음엔 "넘칠 때만 커지고 다시는 안 줄어드는"(grow-only) 방식이었는데, 텍스트를
  줄여도 도형이 안 작아지는 문제가 있어서 "항상 지금 텍스트 양으로 다시 계산"하는 양방향 방식으로
  바꿨다(`syncNoteHeightToText`). 핵심은 `measureNoteFitHeight` 를 부를 때 기준 높이로 항상
  `DEFAULT_NOTE_H`(70)를 주는 것 — 도형의 "지금" 높이를 기준으로 넘기면 자기 자신보다는 안 줄어드는
  grow-only 로 되돌아가 버린다. `note.autoSize`(기본값 true, 백필 없음 — `=== false` 로만 판정해서
  기존 데이터도 자연스럽게 켜진 것으로 취급된다) 가 리사이즈 핸들 드래그가 끝나는 순간(`initResizeHandles`
  의 `onUp`) 딱 한 번 `false` 로 바뀌고, 그 뒤로는 `syncNoteHeightToText` 가 맨 앞에서 바로 손을 뗀다 —
  수동 크기는 텍스트가 아무리 바뀌어도 그대로 유지된다

## Mermaid 변환 규칙

bluishCanvas 는 "그리는 경험"을, Mermaid 는 "클로드와 주고받는 번역 언어"를 담당한다.
변환은 구조(무엇이 무엇과 이어지는지)만 남기고, 좌표·크기·꾸미기처럼 그리기에만 필요한 정보는 일부러 버린다.

**플로우차트 도형 6종은 전부 Mermaid 표준 도형 문법 그대로다** — 왕복 변환에 손실이 없다:

| bluishCanvas | Mermaid |
|---|---|
| 단계 | `N1["텍스트"]` |
| 분기 | `N2{"텍스트"}` |
| 시작/끝 | `N3(["텍스트"])` |
| 준비/설정 | `N4{{"텍스트"}}` |
| 입력 | `N5[/"텍스트"/]` |
| 출력 | `N6[\"텍스트"\]` |
| 그룹(플로우차트) | `subgraph g1["그룹 이름"] … end` |
| 화살표 | `A --> B`, 라벨이 있으면 `A -->|"라벨"| B` |
| 그룹(마인드맵) | 문서 하나(`mindmap`). 화살표 대신 들여쓰기로 계층을 표현한다 |
| 도형 안 줄바꿈 | 도형 텍스트의 실제 줄바꿈 ↔ `<br/>` (양방향 — 내보낼 때 변환하고, 가져올 때(`<br/>`·`<br>` 둘 다) 다시 실제 줄바꿈으로 되돌린다) |

**마인드맵 문법은 도형 토큰을 4종 구분한다**(사각형 `[]`, 육각형 `{{}}`, 둥근사각형 `()`, 원 `(())`) — 단계·
분기·시작/끝·준비/설정은 각각 이 중 하나로 정확히 왕복되고(문법만 flowchart 때와 다를 뿐, 도형 정보 자체는
안 사라진다), 입력/출력만 대응되는 토큰이 없어서 대체된다:

| bluishCanvas | 마인드맵 문법 | 비고 |
|---|---|---|
| 단계 | `id[텍스트]` | 왕복 손실 없음 |
| 준비/설정 | `id{{텍스트}}` | 왕복 손실 없음 |
| 분기 | `id(텍스트)` (둥근 사각형) | 왕복 손실 없음(문법만 다름) |
| 시작/끝 | `id((텍스트))` (원) | 왕복 손실 없음(문법만 다름) |
| 입력 / 출력 | `id[텍스트]` (사각형) | 대체 + 경고 — 대응 토큰이 없어 둘 다 사각형이 되고, 단계와도 구분이 안 된다 |

**재배치(⇄) 버튼은 이 대체를 실제 도형에도 그대로 반영한다** — 마인드맵 그룹을 재배치하면 입력/출력 도형은
캔버스에서도 실제로 사각형(단계)으로 바뀐다(내보내기 경고에서만 알려주고 화면은 그대로인 채로 남지 않도록).
분기/시작·끝/준비·설정/단계는 왕복 손실이 없으므로 재배치해도 원래 모양 그대로 유지된다.

의도적으로 사라지는 정보: 화살표가 도형의 어느 변에서 나가는지, 좌표/크기, 꾸미기(배경색·글자크기·정렬·테두리),
마인드맵 안 화살표의 라벨(Mermaid 마인드맵 문법에 라벨이 없다), 입력/출력 도형의 원래 모양(마인드맵에 대응
토큰이 없어 사각형으로 합쳐지고, 재배치하면 실제로도 사각형이 된다).

변환에서 제외되고 경고로 알려주는 것: 타입 미지정 도형과 거기 딸린 화살표, 타입이 서로 다른 도형을 잇는 화살표,
그룹에 속하지 않은 마인드맵 도형, 트리가 아닌 마인드맵 그룹(순환 / 중심 여러 개 / 화살표가 두 개 들어오는 도형).

**가져오기(Import)는 위 표의 반대 방향**이다. Mermaid 텍스트에는 좌표가 없어서, 파싱으로 구조만 알아낸 뒤
타입에 맞는 검증된 레이아웃 라이브러리(둘 다 CDN으로 불러온다)로 좌표를 계산한다. flowchart 는
[dagre](https://github.com/dagrejs/dagre)를 쓰고, `subgraph`는 dagre 의 "compound"(묶음) 기능으로 묶어서
레이아웃에서도 자연스럽게 뭉치게 한다. mindmap 은 [d3-hierarchy](https://github.com/d3/d3-hierarchy) 의
방사형(radial) 트리 레이아웃을 쓴다 — 루트를 중심에 두고, 각 도형의 위치는 **자기 직속 부모 위치 +
고정 길이(edgeLength) × 자기 각도 방향**으로 재귀적으로 정해진다(중심으로부터의 절대 거리가 아니라
매번 바로 위 부모를 기준으로 계산). 자식들이 부모 둘레에 균등한 각도로 퍼지고, 깊이가 깊어질수록 그만큼
더 바깥으로 나간다(실제 Mermaid 공식 렌더러가 마인드맵엔 dagre 가 아니라 이런 방사형 엔진을 쓰는 것과
맞춘 것). 중심에서 뻗어나가는 가지(1단계 자식)가 N개면 가지마다 정확히 360°/N 을 중심각으로 삼고, 그
가지의 모든 후손은 그 중심각 기준 ±(180°/N)×1.15(15% 여유) 범위 밖으로 못 나가게 부채꼴로 제한한다 —
이 제한이 없으면 자손이 많은 가지가 전체 원의 대부분을 차지해버려 가지끼리 후손이 뒤섞여 보인다.

이 고정 길이(edgeLength)는 트리 전체가 공유하는 하나의 값이 아니라 **가지마다 따로** 계산한다 — 어떤
가지가 자식을 많이 둬서 부채꼴 안이 촘촘해져도, 자식이 없거나 적은 다른 가지는 그 사정과 무관하게 짧게
유지된다(부모-자식 화살표 길이는 "같은 가지 안에서는" 항상 똑같다). 각 가지의 길이는 플로우차트(dagre)의
부모-자식 기본 간격과 비슷한 짧은 값에서 시작해서, 그 가지 자신에게 실제로 겹칠 위험이 있을 때만(정렬된
사슬 형태로 두 도형이 같은 방향에 있거나, 부채꼴이 좁아 형제끼리 촘촘한 경우, 또는 가지 개수 자체가
많아 가지끼리 부딪힐 때) 그 위험을 해소하는 최소한만큼만 늘어난다 — 겹침 회피가 항상 최우선이고, 그걸
만족하는 선에서 최대한 짧게 유지한다. 파싱은
정규식/스캐너 기반의 직접 구현(별도 Mermaid
파서 라이브러리 없음)이라 문법을 완벽히 따르지 않지만, 알아볼 수 없는 줄은 건너뛰고 나머지는 최대한 살리는
쪽으로 관대하게 짰다 — id 문자도 영문/숫자로 제한하지 않고 한글을 포함해 폭넓게 허용한다(이 앱의 목적
자체가 클로드와의 한글 소통이라, Claude 가 만드는 노드 id가 한글일 가능성이 높기 때문). 붙여넣은 텍스트에
flowchart/mindmap 블록이 여러 개 있으면 각각 따로 레이아웃한 뒤 서로 겹치지 않게 나란히 배치한다. 가져온
도형은 텍스트 양에 맞춰 처음부터 충분한 높이로 만들어진다(위 "텍스트에 맞춘 자동 크기 조정" 참고).

**그룹화와 배치**: 한 번의 가져오기로 생긴 도형은 반드시 어떤 그룹엔가 속한다 — flowchart 의 `subgraph`는
그대로 그룹이 되고, subgraph 밖의 낱개 도형들은(그룹 중첩을 지원하지 않아서 subgraph 그룹 안으로 합칠 수
없으므로) "가져온 도형 N"이라는 이름의 그룹 하나로 따로 묶인다. mindmap 은 원래대로 블록 하나가 그룹
하나다. 배치는 현재 페이지에 이미 있는 모든 도형의 전체 경계 상자를 구해서, 그 바깥의 빈 자리(가로로
넓게 퍼진 캔버스면 아래쪽에, 세로로 긴 캔버스면 오른쪽에)에 놓는다 — 그래서 가져온 내용이 기존 도형/그룹과
뒤섞이지 않는다. 기존 내용이 하나도 없으면 원점 근처에 놓는다. 어느 경우든 다 만든 뒤에는 화면(팬)을 방금
가져온 도형들의 한가운데로 옮겨서 바로 보여준다(줌은 그대로, 인스턴트 이동 — 기존 `panToNote`와 같은 방식).

반영은 all-or-nothing 이다 — 파싱·레이아웃 전부를 로컬 임시 배열에 먼저 쌓아보고, 끝까지 성공했을 때만
실제 캔버스 상태에 한 번에 반영하고 실행취소 한 단계로 커밋하므로, 중간에 실패해도 기존 캔버스가 오염되지
않는다.

**재배치**는 "내보냈다가 곧바로 다시 가져오기"와 원리가 같지만, 도형을 지우고 새로 만드는 대신 다시 계산된
좌표를 그 도형의 x,y 에만 덮어쓴다 — 그래서 배경색·자동크기 상태(`autoSize`)·수동 리사이즈한 크기(w,h) 같은
Mermaid 에 안 담기는 정보를 전혀 안 잃는다. `generateMermaid()`가 전역 `notes`/`arrows`/`groups`를 읽는
순수 함수라는 점을 이용해서, 범위만 담은 Export 결과를 얻으려고 계산하는 동안만 그 세 전역을 선택 범위로
잠깐 바꿔치기했다가(동기 함수라 그 사이에 다른 코드가 끼어들 일이 없어 안전) 끝나면 원래대로 되돌린다.
다시 파싱한 뒤에는 각 파싱된 노드의 id(export 가 `N<note.id>` 형식으로 붙였던 것)에서 원래 note.id 를
역으로 추출해 그 도형만 옮긴다 — export 과정에서 빠지는 도형(타입 미지정, 그룹 없는 마인드맵 도형 등)은
재배치 텍스트에도 없으므로 이동 루프에서 아예 안 건드려지고 원래 자리에 그대로 남는다(도형이 사라지는
사고를 막기 위해 "지우고 새로 만들기"가 아니라 "살아남은 것만 옮기기"로 설계했다). 여러 블록을 겹치지
않게 늘어놓는 패킹 로직(`packBlocksLocally`)은 가져오기 배치와 공유하고, 마지막에 어디를 중심으로 삼을지만
다르다 — 가져오기는 기존 캔버스 내용 바깥, 재배치는 원래 그 범위가 있던 자리의 중심(`placeBlocksAtCenter`).
